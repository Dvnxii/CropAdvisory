# Fasal — Agentic Crop Advisory System

Fasal is an AI-based crop advisory system that uses an agent to decide what information it needs before giving an answer.

Instead of using a fixed RAG pipeline for every question, the agent can choose between three tools:

- Agronomy knowledge search
- Soil organic carbon prediction
- Weather forecast

Depending on the question, it can use one tool, multiple tools, or none. The tool calls are also recorded so that the reasoning process can be checked later.

## Why an Agent?

A normal RAG system generally follows the same process every time:

```text
Question → Retrieve documents → Generate answer
```

That is not always necessary.

For example:

- **"Why are my wheat leaves yellowing?"** → Search the agronomy knowledge base
- **"My soil test shows pH 6.2, N 250, P 18..."** → Use the soil model
- **"Should I spray tomorrow?"** → Check the weather
- **"Based on my soil test and this week's weather, what should I do?"** → Use multiple tools

The agent decides which tools are useful for each question.

## How the Agent Works

The Gemini function-calling loop is handled manually in `app/agent.py`.

Automatic function calling is disabled so that the application can keep track of every tool call.

The basic flow is:

```text
User Question
      ↓
     Gemini
      ↓
Choose a tool
      ↓
Execute tool
      ↓
Send result back to Gemini
      ↓
Choose another tool or generate answer
      ↓
Final Answer
```

For every tool call, the application records information such as:

```text
round
tool name
arguments
result
execution time
```

The loop stops when Gemini returns a normal text response or when the maximum number of tool-call rounds is reached.

The default value of `MAX_TOOL_CALL_ROUNDS` is `6`.

## Tools

| Tool | Technology | Purpose |
|---|---|---|
| `search_agronomy_knowledge` | ChromaDB + embeddings | Search information about crops, diseases, pests, fertilizers, irrigation and soil health |
| `predict_soil_organic_carbon` | RandomForestRegressor | Estimate soil organic carbon from soil-test values |
| `get_weather_forecast` | Open-Meteo | Get current weather and forecast information |

### 1. Agronomy Knowledge Search

The knowledge base contains local agronomy documents stored under:

```text
data/agronomy_knowledge/
```

The documents are indexed in ChromaDB.

When `GEMINI_API_KEY` is available, Gemini embeddings are used through `GeminiEmbeddingFunction`.

Without a Gemini key, the project uses a local:

```text
TF-IDF → TruncatedSVD
```

embedding pipeline.

The local embedding model is saved with joblib so that the tests can run without requiring an external API.

### 2. Soil Organic Carbon Model

The soil prediction tool uses:

```text
RandomForestRegressor
```

The model predicts soil organic carbon based on the available soil-test information.

The current test R² is approximately:

```text
0.71
```

The training data is generated by:

```text
scripts/generate_soil_data.py
```

and the model is trained using:

```text
scripts/train_soil_model.py
```

### 3. Weather Tool

Weather information comes from Open-Meteo.

No API key is required.

The tool provides current conditions and forecasts for up to seven days. This can be useful for questions related to irrigation, spraying, rainfall and frost.

## Installation

### Requirements

Python and the packages listed in `requirements.txt` are required.

Install the dependencies:

```bash
pip install -r requirements.txt
```

Create the environment file:

```bash
cp .env.example .env
```

Add your Gemini API key to `.env`:

```env
GEMINI_API_KEY=your_key_here
```

### Train the Soil Model

The soil dataset can be generated using:

```bash
python scripts/generate_soil_data.py
```

Then train the model:

```bash
python scripts/train_soil_model.py
```

This creates:

```text
data/soil_oc_model.joblib
```

### Start the API

Run:

```bash
uvicorn app.main:app --reload --port 8000
```

The API will be available at:

```text
http://localhost:8000
```

The ChromaDB index is created automatically the first time the application starts.

A `/reindex` option is also available when the knowledge base needs to be rebuilt.

## Using the API

Send a POST request to `/advise`:

```bash
curl -X POST http://localhost:8000/advise \
  -H "Content-Type: application/json" \
  -d '{
    "message": "My wheat field soil test shows pH 6.4, N 220 kg/ha, P 15 kg/ha, K 200 kg/ha, clay 38%, sand 28%, rainfall 850mm, temp 24C, moisture 22%. Leaves are also yellowing from the bottom up. What should I do?"
  }'
```

A response looks like:

```json
{
  "answer": "...",
  "tool_trace": [
    {
      "round": 1,
      "tool": "predict_soil_organic_carbon",
      "arguments": {},
      "result": {},
      "latency_ms": 4.2
    },
    {
      "round": 1,
      "tool": "search_agronomy_knowledge",
      "arguments": {},
      "result": [],
      "latency_ms": 1.8
    }
  ],
  "rounds_used": 2
}
```

The important part here is `tool_trace`. It shows which tools the agent used while working on the question.

## Testing

The tool layer can be tested without using Gemini.

Run:

```bash
python tests/test_tool_dispatch.py
```

These tests check the tool schemas, dispatch table and individual tool implementations.

This makes it possible to test the main tool functionality without needing a Gemini API key.

## Data and Production Considerations

The soil dataset used by this project is **synthetically generated**.

It was created because a suitable licensed soil-test dataset was not available for the project. The generated data uses agronomically plausible ranges and relationships.

For a real deployment, the model should be retrained using appropriate real-world datasets, such as suitable ICAR or state soil-health data.

The weather service currently uses Open-Meteo. A different weather provider can be configured later if higher-resolution or more location-specific forecasts are required.

The local TF-IDF/SVD embedding option is mainly useful for keeping the project reproducible and usable without an external embedding API. Gemini embeddings can be used when a Gemini API key is available.
